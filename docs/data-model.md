# CineConecta — Modelo de datos

Documentación de las entidades de cada base de datos, tal como las crean los scripts de `db/postgres/` y `db/mongo/init/`.

| Base | Motor | Contiene | Es fuente de verdad de |
|---|---|---|---|
| Relacional | PostgreSQL (esquema `cineconecta`) | 5 tablas, 1 vista, 1 trigger | Cuentas, perfiles, planes, suscripciones y pagos |
| Documental | MongoDB (base `cineconecta`) | 4 colecciones | Catálogo, "Mi lista", actividad de visualización y administradores |

**Regla de integración:** MongoDB guarda solo los **identificadores** de PostgreSQL (`accountId`, `profileId`, `planIdAtStart`), nunca copias de sus tablas. PostgreSQL no guarda ningún identificador de MongoDB. Las referencias van siempre de MongoDB hacia PostgreSQL, y ninguna operación escribe en las dos bases a la vez.

---

## 1. PostgreSQL

**Convenciones**
- Los nombres se escriben sin comillas, así que PostgreSQL los guarda en minúsculas (`accountId` se guarda como `accountid`). En este documento se escriben en camelCase, como en el modelo suministrado.
- Las fechas son `TIMESTAMPTZ`: instantes absolutos, guardados en UTC.
- Los identificadores son `INTEGER GENERATED BY DEFAULT AS IDENTITY`.
- Ninguna fila se borra: la aplicación no tiene permiso de DELETE.

### Diagrama de relaciones

```
ACCOUNTS 1 ──< N PROFILES
ACCOUNTS 1 ──< N SUBSCRIPTIONS >── N 1 PLANS
SUBSCRIPTIONS 1 ── 1 PAYMENTS
```

### 1.1 `accounts` — cuentas de los titulares

| Columna | Tipo | Nulo | Por defecto | Descripción |
|---|---|---|---|---|
| `accountId` | INTEGER | No | identity | Identificador de la cuenta (PK) |
| `fullName` | VARCHAR(150) | No | | Nombre completo del titular |
| `email` | VARCHAR(254) | No | | Correo de acceso |
| `passwordHash` | VARCHAR(255) | No | | Hash BCrypt de la contraseña |
| `createdAt` | TIMESTAMPTZ | No | `now()` | Fecha de registro |

| Restricción / índice | Tipo | Regla |
|---|---|---|
| `pk_accounts` | PRIMARY KEY | `accountId` |
| `ux_accounts_email_ci` | UNIQUE INDEX | `LOWER(email)`: correo único sin distinguir mayúsculas |
| `ck_accounts_email` | CHECK | El correo contiene `@` después del primer carácter |

### 1.2 `plans` — planes de suscripción

| Columna | Tipo | Nulo | Por defecto | Descripción |
|---|---|---|---|---|
| `planId` | INTEGER | No | identity | Identificador del plan (PK) |
| `name` | VARCHAR(60) | No | | Nombre del plan |
| `price` | NUMERIC(12,2) | No | | Precio en pesos colombianos |
| `maxProfiles` | INTEGER | No | | Máximo de perfiles activos |
| `isActive` | CHAR(1) | No | `'Y'` | **Columna nueva.** `'N'` = no se ofrece en nuevas contrataciones |

| Restricción / índice | Tipo | Regla |
|---|---|---|
| `pk_plans` | PRIMARY KEY | `planId` |
| `uq_plans_name` | UNIQUE | `name` |
| `ck_plans_price` | CHECK | `price > 0` |
| `ck_plans_maxprofiles` | CHECK | `maxProfiles` entre 1 y 10 |
| `ck_plans_isactive` | CHECK | `isActive IN ('Y','N')` |

`isActive` es un cambio estructural al modelo suministrado, justificado por la gestión de planes del administrador. El precio y el máximo de perfiles no se pueden modificar después de crear el plan: `cine_app` solo tiene permiso de UPDATE sobre `name` e `isActive`.

### 1.3 `profiles` — perfiles de visualización

| Columna | Tipo | Nulo | Por defecto | Descripción |
|---|---|---|---|---|
| `profileId` | INTEGER | No | identity | Identificador del perfil (PK) |
| `accountId` | INTEGER | No | | Cuenta a la que pertenece (FK) |
| `name` | VARCHAR(60) | No | | Nombre del perfil |
| `maxAgeRating` | INTEGER | No | | Clasificación máxima permitida |
| `isActive` | CHAR(1) | No | `'Y'` | `'N'` = desactivado (conserva su historial) |

| Restricción / índice | Tipo | Regla |
|---|---|---|
| `pk_profiles` | PRIMARY KEY | `profileId` |
| `fk_profiles_account` | FOREIGN KEY | `accountId` → `accounts` |
| `ux_profiles_name_ci` | UNIQUE INDEX | `(accountId, LOWER(name))`: nombre único dentro de la cuenta. También sirve de índice para la FK |
| `ck_profiles_agerating` | CHECK | `maxAgeRating` entre 0 y 18 |
| `ck_profiles_isactive` | CHECK | `isActive IN ('Y','N')` |

Que los perfiles activos no superen el máximo del plan vigente lo controla la aplicación.

### 1.4 `subscriptions` — suscripciones

| Columna | Tipo | Nulo | Por defecto | Descripción |
|---|---|---|---|---|
| `subscriptionId` | INTEGER | No | identity | Identificador (PK) |
| `accountId` | INTEGER | No | | Cuenta que contrata (FK) |
| `planId` | INTEGER | No | | Plan contratado (FK) |
| `startsAt` | TIMESTAMPTZ | No | | Inicio de la vigencia (incluido) |
| `endsAt` | TIMESTAMPTZ | No | | Fin de la vigencia (excluido) |

| Restricción / índice | Tipo | Regla |
|---|---|---|
| `pk_subscriptions` | PRIMARY KEY | `subscriptionId` |
| `fk_subscriptions_account` | FOREIGN KEY | `accountId` → `accounts` |
| `fk_subscriptions_plan` | FOREIGN KEY | `planId` → `plans` |
| `ck_subscriptions_30_days` | CHECK | `endsAt = startsAt + 720 horas` (30 días exactos) |
| `ex_subscriptions_no_overlap` | EXCLUDE (GiST) | Una misma cuenta no puede tener rangos `[startsAt, endsAt)` superpuestos. Si dos compras simultáneas se cruzan, la segunda falla con `23P01` |
| `ix_subscriptions_account_starts` | INDEX | `(accountId, startsAt DESC)`: historial y suscripción vigente |
| `ix_subscriptions_plan` | INDEX | `planId`: FK e informe de ingresos |
| `tg_subscription_requires_payment` | CONSTRAINT TRIGGER (diferido) | Al hacer COMMIT, rechaza una suscripción sin pago |

La tabla es un historial: la aplicación solo puede insertar, nunca modificar. Una suscripción está **vigente** si `startsAt ≤ now() < endsAt`; ese dato se calcula, no se guarda.

### 1.5 `payments` — pagos

| Columna | Tipo | Nulo | Por defecto | Descripción |
|---|---|---|---|---|
| `paymentId` | INTEGER | No | identity | Identificador (PK) |

| `paidAt` | TIMESTAMPTZ | No | `now()` | Fecha del pago |
| `amount` | NUMERIC(12,2) | No | | Monto: copia del precio del plan al pagar |
| `reference` | VARCHAR(100) | No | | Referencia del pago simulado |

| Restricción / índice | Tipo | Regla |
|---|---|---|
| `pk_payments` | PRIMARY KEY | `paymentId` |
| `fk_payments_subscription` | FOREIGN KEY | `subscriptionId` → `subscriptions` |

**Exactamente un pago por suscripción.** `uq_payments_subscription` garantiza "como máximo uno" y el trigger `tg_subscription_requires_payment` garantiza "al menos uno". Los pagos rechazados no se guardan.

## 2. MongoDB

**Convenciones**
- Cada colección tiene un validador `$jsonSchema` (`validationLevel: strict`, `validationAction: error`).
- Los identificadores que vienen de PostgreSQL y los valores numéricos se guardan como `int` (32 bits). En Java son `Integer`.
- Las fechas se guardan como `date` (UTC).
- No hay `additionalProperties: false`, para que el catálogo pueda incorporar campos nuevos.

### 2.1 `contents` — catálogo

Un documento por película, serie o documental, con la forma que escribe el módulo `catalog` desde la clase `Content` (Spring Data MongoDB). Es una colección **polimórfica**:
- Los **metadatos comunes** van en la raíz del documento.
- Los **datos propios de cada tipo** van en el subdocumento `contentDetails`. Spring Data le agrega el campo `_class` con el alias del tipo (`MOVIE`, `SERIES` o `DOCUMENTARY`).
- Las temporadas y los episodios van **embebidos** en la serie, porque se leen juntos al abrirla, su tamaño es acotado y no existen fuera de ella.

**Campos comunes** (todos obligatorios desde la creación: la aplicación no guarda borradores incompletos)

| Campo | Tipo BSON | Descripción |
|---|---|---|
| `_id` | objectId | Identificador estable; nunca se reutiliza |
| `_class` | string | Lo agrega Spring Data (`Content`) |
| `version` | int o long | Control de concurrencia optimista (`@Version`): una edición simultánea se rechaza |
| `type` | string | `MOVIE`, `SERIES` o `DOCUMENTARY`. No cambia después de crearse |
| `status` | string | `DRAFT`, `PUBLISHED` o `RETIRED` |
| `title` | string (1–200) | Título |
| `titleNormalized` | string | Título sin tildes ni mayúsculas: para buscar y para impedir duplicados |
| `synopsis` | string (1–2000) | Sinopsis |
| `year` | int (1888–2100) | Año de estreno |
| `ageRating` | int (0–18) | Clasificación por edad |
| `posterUrl` | string | URL de la portada: absoluta (`http://` o `https://`) o ruta servida por la aplicación (`/images/posters/...`) |
| `genres` | array de string (≥ 1) | Géneros, sin repetidos |
| `countries` | array de string (≥ 1) | Países de producción, código ISO de 2 letras (`CO`) |
| `audioLanguages` | array de string (≥ 1) | Idiomas de audio, código de idioma (`es`, `en`, `pt-BR`) |
| `subtitleLanguages` | array de string (puede ir vacío) | Idiomas de subtítulos |
| `schemaVersion` | int ≥ 1 | Versión del esquema del documento, para la evolución del catálogo |
| `createdAt`, `updatedAt` | date | Auditoría |
| `contentDetails` | object | Datos propios del tipo (ver abajo) |

**`contentDetails` según el tipo**

| Tipo | Campo | Tipo BSON | Obligatorio | Descripción |
|---|---|---|---|---|
| `MOVIE` | `durationSeconds` | int ≥ 1 | Sí | Duración |
| `MOVIE` | `directors` | array de string (≥ 1) | Sí | Dirección |
| `MOVIE` | `cast` | array (≥ 1) de `{ name, character? }` | Sí | Reparto; el personaje es opcional ("cuando se conozca") |
| `DOCUMENTARY` | `durationSeconds` | int ≥ 1 | Sí | Duración (una sola pieza) |
| `DOCUMENTARY` | `directors` | array de string (≥ 1) | Sí | Dirección |
| `DOCUMENTARY` | `topics` | array de string (≥ 1) | Sí | Temas abordados |
| `DOCUMENTARY` | `interviewees` | array de string | No | Personas entrevistadas |
| `DOCUMENTARY` | `sources` | array de string | No | Fuentes o instituciones participantes |
| `SERIES` | `seasons` | array de temporada | Sí | Temporadas |

**Temporada** `{ number, description, episodes[] }` y **episodio** `{ episodeId, number, title, synopsis, durationSeconds }`. Todos sus campos son obligatorios. `number` es un int ≥ 1 y `episodeId` es un **UUID en texto** que genera la aplicación y no cambia.

**Regla por estado:** una serie en `DRAFT` puede quedar sin temporadas o con temporadas vacías mientras se arma. En `PUBLISHED` o `RETIRED` debe tener al menos una temporada, y cada temporada al menos un episodio.

| Índice | Campos | Consulta |
|---|---|---|
| `ix_contents_status_type_age` | `status, type, ageRating` | Búsqueda del cliente: publicados, por tipo, con clasificación ≤ la del perfil (regla ESR: igualdades primero, el rango al final). También sirve al listado del administrador por estado y tipo |
| `ix_contents_status_genres_age` | `status, genres, ageRating` | Filtro por género |
| `ix_contents_status_audio_age` | `status, audioLanguages, ageRating` | Filtro por idioma de audio |
| `ux_contents_title_year` | `titleNormalized, year` (único) | Impide registrar dos veces el mismo título en el mismo año |
| `ux_contents_episode_id` | `contentDetails.seasons.episodes.episodeId` (único, parcial) | Resolver un episodio; impide repetir su ID entre series |

Los índices de género e idioma van separados porque MongoDB no permite dos arreglos en un mismo índice compuesto. La búsqueda por título es un "contiene" (expresión regular sobre `titleNormalized`), que no puede aprovechar un índice por rangos: se resuelve combinada con los demás filtros, que sí usan índice.

**Lo controla la aplicación:** que los números de temporada y de episodio no se repitan dentro de una serie (son elementos del mismo documento, y un índice único no los compara entre sí), que el tipo no cambie y las transiciones de estado.

### 2.2 `my_lists` — "Mi lista"

Un documento por perfil, con **referencias simples** a `contents`. El arreglo va en un documento propio porque el perfil, que es el lado más consultado, vive en PostgreSQL.

| Campo | Tipo BSON | Obligatorio | Descripción |
|---|---|---|---|
| `_id` | int | Sí | `profileId` de PostgreSQL |
| `contentIds` | array de objectId | Sí | Contenidos guardados, sin repetidos (`uniqueItems`) |
| `updatedAt` | date | Sí | Última modificación |

- Se agrega con `$addToSet` y se quita con `$pull`.
- Solo se agregan contenidos publicados y permitidos para el perfil.
- Si un contenido de la lista se retira después, no se quita: se muestra marcado como retirado, consultando su `status` en `contents`.
- No necesita índices adicionales: la consulta "Mi lista del perfil" usa el índice de `_id`.

```json
{
  "_id": 42,
  "contentIds": [ { "$oid": "6740a1f0c3b2a1d4e5f60001" }, { "$oid": "6740a1f0c3b2a1d4e5f60007" } ],
  "updatedAt": { "$date": "2026-11-15T01:20:00Z" }
}
```

### 2.3 `playback_sessions` — sesiones de reproducción

Un documento por sesión. Es un historial: una sesión cerrada no se modifica. Es la base de "Continuar viendo", del informe de consumo y de la analítica.

| Campo | Tipo BSON | Obligatorio | Descripción |
|---|---|---|---|
| `_id` | objectId | Sí | Identificador de la sesión |
| `accountId` | int | Sí | Cuenta (PostgreSQL) |
| `profileId` | int | Sí | Perfil que reproduce (PostgreSQL) |
| `contentId` | objectId | Sí | Película, documental o serie |
| `episodeId` | string (UUID) | Solo en series | Episodio reproducido |
| `contentType` | string | Sí | `MOVIE`, `SERIES` o `DOCUMENTARY` (copia al iniciar) |
| `durationSeconds` | int ≥ 1 | Sí | Duración de la pieza (copia al iniciar) |
| `planIdAtStart` | int | Sí | Plan de la suscripción vigente al iniciar (copia de PostgreSQL) |
| `startedAt` | date | Sí | Inicio |
| `endedAt` | date o null | Sí | Fin; `null` mientras la sesión está abierta |
| `lastActivityAt` | date | No | Último control o aviso del reproductor. Opcional para sesiones anteriores |
| `playingSince` | date o null | No | Interno: inicio del tramo en reproducción; `null` en pausa |
| `watchedSeconds` | int ≥ 0 | Sí | Tiempo realmente visto, sin los saltos de "avanzar" |
| `lastPosition` | int ≥ 0 | Sí | Última posición alcanzada |
| `finished` | bool | Sí | El reproductor la finalizó al llegar al final del contenido (no hay botón de finalizar) |

**Datos copiados.** `contentType`, `durationSeconds` y `planIdAtStart` son fotos inmutables del momento de inicio. No pueden quedar inconsistentes porque registran un hecho histórico, y permiten calcular los informes sin consultar el catálogo ni PostgreSQL por cada sesión.

**Informe de consumo.** `ConsumptionApi.byPlanAndType` selecciona las sesiones iniciadas en el intervalo `[inicio, fin)`. Suma los segundos vistos y cuenta una sola vez cada perfil dentro de cada plan y tipo. El plan usado es `planIdAtStart`. Los segundos se convierten a minutos con dos decimales después de sumar. El módulo de informes puede consultar en PostgreSQL el nombre de cada plan.

**Completado** (calculado, no se guarda): `finished = true` o `lastPosition ≥ 90 %` de `durationSeconds`. Lo completado sale de "Continuar viendo" y se marca como "✓ Visto" en el catálogo, con la opción de volver a verlo desde el inicio (una sesión nueva).

| Índice | Campos | Consulta |
|---|---|---|
| `ix_sessions_profile_started` | `profileId, startedAt -1` | "Continuar viendo" (regla ESR: igualdad + orden) |
| `ix_sessions_started` | `startedAt` | Informes y analítica por período |
| `ix_sessions_content_started` | `contentId, startedAt` | Analítica por contenido |
| `ix_sessions_open` | `endedAt, startedAt` | Cierre de sesiones abandonadas |

**"Continuar viendo" se calcula desde esta colección** (no hay una colección de progreso):
1. Filtrar por `profileId`.
2. Ordenar por `startedAt` descendente (el orden lo resuelve el índice).
3. Agrupar por pieza (`contentId` + `episodeId`) y tomar la sesión más reciente con `$first`.
4. Descartar las completadas y los contenidos retirados.
5. Ordenar por actividad reciente.

Mientras el reproductor está visible y en marcha, guarda la posición y el tiempo visto cada 10 segundos. Una sesión se cierra si pasa un minuto sin actividad. Se conserva la posición del último aviso y no se cuenta como visto el tiempo posterior. Si se retoma una sesión cerrada, se inicia una nueva desde esa posición y se consulta de nuevo el plan vigente.

```json
{
  "_id": { "$oid": "6741b2c0d4e5f6a7b8c90001" },
  "accountId": 17,
  "profileId": 42,
  "contentId": { "$oid": "6740a1f0c3b2a1d4e5f60001" },
  "episodeId": "9a1b2c3d-4e5f-4a6b-8c7d-0e1f2a3b4c02",
  "contentType": "SERIES",
  "durationSeconds": 2820,
  "planIdAtStart": 2,
  "startedAt": { "$date": "2026-11-18T01:05:00Z" },
  "endedAt": { "$date": "2026-11-18T01:40:00Z" },
  "playingSince": null,
  "watchedSeconds": 1980,
  "lastPosition": 2400,
  "finished": false
}
```

## 3. Relaciones entre las dos bases

| Identificador | Nace en | Dónde aparece en MongoDB | Cómo se verifica |
|---|---|---|---|
| `accountId` | `accounts` | `playback_sessions` | Se toma del usuario autenticado |
| `profileId` | `profiles` | `_id` de `my_lists`, `playback_sessions` | Verificación V1 en PostgreSQL antes de escribir: el perfil existe, está activo y pertenece a la cuenta |
| `planIdAtStart` | `subscriptions` | `playback_sessions` | Se lee de la suscripción vigente en el instante de inicio de la sesión (`SubscriptionApi.planAt`, que consulta `subscriptions` con JPA) |
| `contentId` | `contents` | `my_lists`, `playback_sessions` | La aplicación lo resuelve contra `contents`; nunca se borra ni se reutiliza |
| `episodeId` | `contents.contentDetails.seasons.episodes` | `playback_sessions` | La aplicación lo resuelve contra `contents` |
